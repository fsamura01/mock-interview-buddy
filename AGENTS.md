# Mock Interview Buddy — Agent Guide

## Project Overview

**Whiteboarder Interview Studio** is a real-time collaborative system design interview platform. An interviewer and one or more candidates share a live architecture canvas where they can place components, draw connections, annotate, and chat — all synchronized in real time.

The full product specification lives in [`docs/spec.md`](../docs/spec.md). Read it before making significant changes.

| Layer | Technology |

## Key Conventions

### API / Data Layer

- **All backend calls must go through `src/services/api.ts`** via the `PlatformApi` interface. Never call `fetch` directly from a component.
- The app currently uses the **mock API** (`src/services/mock/mock-api.ts`). Swapping to a real backend means replacing the single line `export const api: PlatformApi = mockApi` in `api.ts`.
- Keep domain types in `src/services/types.ts`. Do not scatter type definitions across components.

### Routing

- Routes live in `src/routes/` and follow TanStack Router's **file-based** conventions.
- **Do not edit `src/routeTree.gen.ts` by hand** — it is auto-generated by the dev server. Add or rename route files instead.
- Dynamic segments use the `$param` convention (e.g., `session.$sessionId.tsx`).

### Build Config

- **Do not add plugins that are already included by `@lovable.dev/vite-tanstack-config`** (TanStack devtools, `viteReact`, `tailwindcss`, `tsConfigPaths`, Nitro, etc.). Adding them twice will break the build. See the comment at the top of `vite.config.ts` for the full list.

### Roles & Permissions

The platform has four roles defined in `types.ts`: `interviewer`, `candidate`, `observer`, `admin`. Enforce role-based logic as described in the permission matrix in `docs/spec.md` (Section 9). Do not add UI actions that bypass role checks.

### Canvas Data Model

| Type | Description |
|---|---|
| `CanvasNode` | A draggable architecture component (service, DB, cache, etc.) |
| `CanvasEdge` | A directed connection between two nodes with a `protocol` label |
| `NodeKind` | `client \| gateway \| service \| database \| cache \| queue \| storage \| cdn \| worker \| external` |

Every canvas mutation goes through `api.createNode`, `api.updateNode`, `api.deleteNode`, `api.createEdge`, or `api.deleteEdge`.

### Real-time Subscription

`api.subscribe(sessionId, onChange)` returns an unsubscribe function. Always call it in a `useEffect` cleanup to avoid memory leaks.

## What Is and Isn't Implemented Yet

### ✅ Implemented (mock only)
- Session list + creation dashboard
- Live board with draggable nodes and edges
- Chat panel
- Audit log panel
- Snapshot save/restore
- Participant presence sidebar

### ❌ Not yet implemented (see `docs/spec.md` Section 2.2)
- Real WebSocket backend
- Authentication (Auth0 / Clerk)
- Free-form drawing
- Undo/redo
- Canvas locking
- Session export
- Observer-only role enforcement in UI
- Admin panel

Do not add placeholder stubs for the above unless the user explicitly asks.

## Development

```bash
# Install dependencies
npm install

# Start dev server (hot reload + route tree generation)
npm run dev
```

The dev server runs on `http://localhost:3000` by default.

## Commit Guidelines

- Keep commits in a **working state** at all times (Lovable syncs on push).
- Use short, imperative commit messages: `Add snapshot panel`, `Fix edge deletion bug`.
- Do not commit `node_modules`, build artefacts, or `.env` files.
